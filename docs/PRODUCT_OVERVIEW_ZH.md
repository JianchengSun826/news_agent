# Tech Newsroom Agent 产品介绍

## 产品定位

Tech Newsroom Agent 是一套面向中文科技新闻团队的本地化、人机协作生产系统。它把候选新闻从来源审核、去重、研究写作、事实核验、图片版权确认，到审核、批准和发布包生成组织成可追踪的批次流程。当前 Phase 1.1 采用 macOS Finder 工作区、Python CLI 与 SQLite，不依赖付费 API，也不会自动抓取、发布或替编辑作出高风险判断。

## 解决的问题

传统的模型辅助写作通常依赖零散提示词、聊天窗口和人工文件命名，容易出现来源与稿件脱节、重复选题、结果导错批次、旧版本覆盖、核验遗漏、图片权利不清以及部分文章提前进入发布等问题。随着批次增大，编辑很难回答三个基本问题：当前做到哪一步、哪些材料属于哪篇文章、整批是否已经满足发布条件。

本产品以 SQLite 保存唯一可信状态，以批次和文章 ID 绑定所有输入、输出和审计记录；文件系统只承载可阅读、可移交的工作材料。确定性代码负责身份、结构、状态和完整性校验，人工负责来源判断、模型交互、图片权利、最终审核和发布。

## 核心能力

| 能力 | 产品行为 |
| --- | --- |
| 候选导入 | 导入经 Google Sheet 审核的 CSV；忽略尾部空行，拒绝缺少必填字段的部分记录。Gemini 的职责在 CSV 生成后结束。 |
| 去重与选题 | 依据公司、产品、事件类型、日期和关键词离线比较；明确的新事件可自动选择，歧义和重复项必须由编辑决定。 |
| 整批内容生产 | 为一个批次生成严格 JSON request；第一个 Claude 对话一次完成研究简报、Markdown 稿件和图片候选。返回结果必须完整覆盖当前文章并匹配批次、请求和文件身份。 |
| 独立事实核验 | 第二个全新 Claude 对话对整批稿件执行一次独立核验，并逐篇返回 PASS/FAIL。失败稿件进入保留历史版本的修订循环，其他稿件无需重做。 |
| 图片与版权 | 每篇最多提供三个候选。编辑必须打开原始落地页和权利页，确认作者、许可、署名与新闻相关性，人工下载原图后才能整批登记。发布包同时保存图片和许可记录。 |
| 发布闸门 | 所有有效文章满足事实核验和图片/无图登记后，操作 05 一次确认整批审核与批准并导出；每个闸门均验证全部有效文章。 |
| 发布交付 | 为每篇文章生成包含正文、元数据、来源、核验报告、图片、许可和检查清单的独立目录，并生成整批 manifest。获得正文和已登记图片即完成本地内容任务；CMS 上传及真实 URL 登记为可选人工后续操作。 |
| 审计与统计 | 关键状态变化记录操作者、原因和 UTC 时间；文章版本、模型 request/result、发布状态和已发布 URL 均可追溯。 |

## 使用体验

每个批次集中在 `workspace/batches/BATCH_ID/`。README 显示当前状态、下一步、当前待上传任务文件及预期返回名和全部文章；`articles/`、`claude/`、`images/` 与 `publish/` 保存规范材料。编辑主要通过 Finder 双击四个编号（02–05） `.command` 文件，完成导入结果、查看审核材料、登记图片，以及一次确认完成审核、批准、导出和刷新。Terminal 可能短暂出现，但日常流程不要求输入长命令。

操作 05 完成后直接打开 `workspace/completed/BATCH_ID/`，每篇只交付正文及可选图片和版权记录。已完成批次集中在首页“已完成”区；系统验证交付后删除该批次 CSV、Claude 文件、研究、核验、历史版本和中间包等过程文件；SQL 去重、权利与审计记录保留。清理中断可重试，未完成批次和外部原文件不受影响。完成稿的人工编辑不会被重新导出覆盖。

README、状态页和图片候选清单是可重建视图，不通过手改文件推进流程。若 Finder 操作失败，同一批次能力仍可通过受支持的 `newsroom batch` CLI 执行。

## 可靠性与安全边界

- Pydantic 在输入边界拒绝未知字段、错误成员和过期结果；SQLite 事务避免半批次写入。
- 内容、图片和发布包先暂存并完整验证，再统一提交；打包失败保留已有发布包和已完成的审核批准，可重试继续导出。
- 数据库升级、旧工作区迁移和恢复具有独占锁、WAL 检查、不可覆盖备份、manifest 哈希、journal、receipt 与回滚证据。
- 来源仅保存 URL、元数据和编辑笔记，不复制第三方全文；图片必须具有明确可用的权利依据。
- 程序不调用模型 API、不自动下载图片、不判断许可是否合法、不自动上传 CMS，也不自动发布新闻。

## 当前范围

当前可用产品是 Scheme C，即 macOS Finder 优先的 Phase 1.1 批次工作流。它适合希望保留人工编辑责任，同时减少文件混乱、状态遗漏和重复操作的小型新闻团队。原生 Scheme A `Newsroom.app` 尚未实现；Web UI、定时任务、自动抓取、云数据库、向量数据库和模型 API 属于未来阶段，必须依据真实批次数据另行设计和批准。

项目下一阶段的判断依据不是自动化程度，而是实际运营数据：重复判断准确率、导入失败率、核验失败与修订频率、图片权利拒绝原因、人工编辑时间，以及最终发布质量。完整操作见 [WORKFLOW_ZH.md](WORKFLOW_ZH.md)，技术边界见 [ARCHITECTURE.md](ARCHITECTURE.md)，阶段规划见 [ROADMAP.md](ROADMAP.md)。
