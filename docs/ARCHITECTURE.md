# Architecture

## Phase 1.1 components

`newsroom.cli` exposes candidate inputs, batch operations, and explicit workspace migration. `newsroom.batch.BatchWorkflow` coordinates durable CSV batches and manual Claude handoffs. `newsroom.batch_release.BatchReleaseWorkflow` validates whole-batch image plans, review, approval, staged packages, and publication URL registration. `newsroom.service.Newsroom` retains focused artifact and state helpers for batch construction and internal recovery; its single-article lifecycle is not a supported user interface. Pydantic v2 models in `newsroom.models` and `newsroom.batch_models` reject unknown fields at input boundaries. `newsroom.dedup` performs deterministic offline event comparison; `newsroom.db` manages SQLite schema and upgrade backups.

SQLite at `data/newsroom.db` is canonical. Fresh initialization creates only `data/` and its database/coordination files. Batch services create `workspace/batches/BATCH_ID/` on demand: `input/` retains CSV and source metadata; `claude/requests/`, `claude/inbox/`, and `claude/archive/` hold manual model exchanges; `articles/ARTICLE_ID/` contains versioned research, drafts, fact-checks, image candidates, and one selected `hero.EXT`; `publish/` contains article packages and `batch-manifest.json`. Top-level legacy artifact roots are not created for new work.

`newsroom.workspace.BatchWorkspace` generates relative-link dashboards, `batch-state.json`, image-candidate views, `OPEN_BATCH.command`, eight action launchers, and `workspace/Migrate Newsroom.command`. These views are disposable and rebuilt from SQLite without advancing workflow. For `REUSED_COMPLETE` articles with an owning batch, immutable ownership keeps material there with relative links; later batches neither edit nor package it. Legacy rows may retain null `owning_batch_id`, so no batch-workspace link is available. Their recorded canonical/legacy paths remain the reference; migration or ownership reconciliation may be needed rather than assuming an original batch exists.

`newsroom.macos.MacOSBatchController` is the macOS-only Finder adapter. Fixed, executable, relocatable zsh launchers locate `pyproject.toml` above themselves and dispatch hidden controller commands. `osascript` supplies selection, confirmation, cancellation, and errors; `open` reveals material. Business validation stays in Python. Launchers contain no user source text or business rules. The supported user sequence and every filename are in [WORKFLOW.md](WORKFLOW.md).

## Provider and trust boundaries

Gemini ends at the reviewed CSV. Claude App receives one content request for the whole eligible batch, then a separate fresh conversation receives one fact-check request. There is no model SDK or network call in the runtime. The application never downloads images, decides that a license is valid, or publishes to a CMS.

Every Claude result is validated for schema, batch/request identity, declared output filename, exact article membership, slugs, and image rights metadata before writes begin. The Finder importer offers one matching inbox JSON, a chooser for multiple matches, or a local picker when none match. Successful import archives original bytes, updates artifacts, creates the next request, and refreshes views. Multi-article imports use one SQLite transaction and staged files. Immutable `batch_requests` retain every content, fact-check, and revision exchange; a newer request ID rejects stale results. Gemini has no post-import role.

## Reliability and human gates

Schema v4 upgrades are additive and back up older databases before changes. SQL uses parameter binding, UTC ISO-8601 timestamps, and append-only state transitions. Content import preserves article versions. One independent fact-check pass returns individual PASS/FAIL reports; failed articles enter revision, while all active articles must pass before the whole batch can register images. A resumable `image-selections.json` draft preserves confirmed choices on cancellation without partially registering images. Image files are staged before a single database transaction; invalid membership, rights confirmation, or local files reject the plan.

Review requires every active article to be `FACT_CHECKED` (or uniformly `IMAGE_READY` for legacy registered images/no-image choices); approval requires `REVIEWED`; packaging requires `APPROVED`. Review/approval and publication URL registration validate all members and commit together. Packages and the complete manifest are staged, validated, and promoted together, with compensation preserving previous packages on failure. Packaging marks the batch `PACKAGED`, leaving articles `APPROVED` until manual publication registration. `EXCLUDED` and `REUSED_COMPLETE` do not participate in gates. Derived view refresh remains retriable.

`newsroom.migration.WorkspaceMigrator` inventories old references and ownership, saves a read-only preflight, verifies SQLite/archive/hash backups, stages canonical trees and regenerated views, switches paths transactionally, and validates references before retaining complete old trees under `data/workspace-migration-recovery/`. For v3-upgraded rows with null ownership, preflight projects an owner only from exactly one active `batch_items` row; reused/excluded links do not count, zero keeps the article in the legacy archive, and two rows block even when both name the same batch. An existing owner likewise requires exactly one active row naming it. The complete projection is immutable plan data, so relationship changes invalidate execute; inferred owners, paths, and workspace versions commit together. Journal and receipt validation bind the projection digest and recheck the resulting owner identities. Journal-bound retained trees are never automatically unlinked or recursively deleted. Failed or interrupted work preserves backups, diagnostics, staging, and recovery material; verified rollback restores original state. Re-entry checks journal, receipt, backup identity, and retained snapshots rather than trusting terminal flags alone.

`newsroom.coordination` holds shared `flock` locks throughout CLI/Finder operations and a nonblocking exclusive lock throughout migration. A persistent migration barrier and read-only journal checks block ordinary access until verified commit cleanup or rollback. Relocation resolves safe local references under the current root. Path escape, symlinks, changed retained trees, and unresolved recovery reject access. Full recovery instructions and the explicit preflight/backup/execute interface are in [WORKFLOW.md](WORKFLOW.md#9-旧工作区迁移与恢复); implementing migration does not authorize skipping rehearsal and confirmation.

Humans remain responsible for Sheet source review, ambiguous duplicate decisions, Claude App upload/download, opening image landing and rights pages, downloading and visually inspecting the image, final review, approval, CMS upload, and publication URL registration.

Default Finder actions are 02, 03 and 05; image registration is no longer a prerequisite. Hash-verified content recommendations and SQLite candidates render image-guide.md, exported alongside each article and included in the delivery receipt and cleanup inventory. Editors download and upload images to Google Drive after local export. Existing registered image files still require their original validation; external handling does not fabricate an image or NO_IMAGE audit record.
