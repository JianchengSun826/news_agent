# 已完成批次只保留最终成果

日期：2026-10-12
阶段：Phase 1.1，本地、人工操作
状态：删除范围已获用户确认；本书面设计待确认

## 用户需求与完成标准

用户确认：获得新闻正文和图片即完成任务。批次完成后，凡不影响 SQLite 重复文章检测且不属于最终正文、图片的过程文件都可以删除。最终成果集中在一个目录；不需要为人工发布保留完整 CMS 包。

成功标准：操作 05 导出成功后，该批次仅留下交付目录及数据库记录；下次导入 CSV 的去重结果不变，已完成批次状态查询和工作区检查仍正常。未完成批次保持原工作流程。不增加模型 API、联网操作、自动发布或后台清理任务。

## 采用的方式

采用“最终成果验证、数据库引用切换、过程文件清理”的方式。单纯删除文件会留下失效的数据库路径，导致工作区检查失败；长期归档过程材料又不符合用户希望释放空间的目的。

SQLite 保留全部 candidates、articles、batch_items、batches、图片权利和审计记录，包括指纹、事件 ID、公司、产品、事件类型、日期、核心事实、关键词、来源、版本、核验结论、审批和可选发布 URL。去重继续使用既有 SQL 查询和判定规则，不以最终文件是否存在作为去重依据。

## 文件范围

最终目录保持现有布局：

```text
workspace/completed/BATCH_ID/
  article-slug/
    article.md
    hero.EXT                 # 有图时
    image-license.json       # 有图时，供实际发布署名和授权使用
  .newsroom-export.json       # 隐藏的文件完整性记录
```

删除成功完成批次的 `workspace/batches/BATCH_ID/` 过程目录，包括 CSV 副本、来源文件视图、Claude 请求和返回文件、inbox、修订版本、研究简报、核查报告、图片推荐及选择草稿、过程图片、完整发布包、README、状态视图及批次启动器。批次目录中的自定义过程文件也在已确认删除范围内，不再仅清理字节相同的重复文件。

原始 CSV、JSON 和图片若位于下载目录或其他外部位置，不属于程序管理的批次副本，不删除。项目源码、配置、提示词模板、全局工作区入口、SQLite 及其备份、迁移恢复树、其他批次、未归属历史资料不在本次清理范围内。数据库和迁移备份可能仍含历史记录，本功能不处理备份销毁。

## 数据与工作区接口

增加持久化的批次保留记录，记录 `CLEANING` 或 `FINAL_ONLY`、交付路径、清理对象清单、actor、reason 和时间。这是文件保留状态，独立于 `PACKAGED` / `PUBLISHED` 工作流状态。升级初始化 SQL、数据库版本及 DATA_MODEL 文档；旧批次不会因初始化或刷新而被自动删除。

引用切换在一个 SQLite 事务内完成：本批次拥有的文章 `draft_path` 改为最终 `article.md`，已选图片 `image_path` 改为最终图片；研究、核查、过程图片提示词和请求返回文件路径解除引用。`batch_requests.request_path` 沿用当前 NOT NULL 约束，以空字符串表示已明确清理，并保留请求 ID、类型、返回 SHA-256、完成状态和时间。所有读取方必须识别这种已清理路径，不能将空字符串当成仓库根目录。

不得删除候选、文章或审计行，也不得通过清理改变文章版本、核验结论、审批状态、无图决定或候选去重字段。仅处理本批次拥有的素材；若其他批次仍有实际文件引用落在待删目录，预检拒绝清理并报告引用，不能留下另一个批次的悬空路径。

已完成批次的 status、snapshot、刷新和相同 CSV 重入仍可使用。根 README 只链接最终目录，移除已删除的历史目录链接；刷新不重新创建该批次的过程目录或请求。操作 05 对 `FINAL_ONLY` 批次返回现有交付目录，不再次批准或重新打包。缺失或损坏的交付必须明确报错。通过正常人工操作编辑最终正文不触发过程材料重建；重复打开无需覆盖文件，完整性检查会报告与原始交付不一致。

依赖旧过程材料的内容修订、历史请求导入或完整包重建操作，对已清理批次明确说明材料已清理，不能尝试读取旧路径。可选人工发布 URL 登记继续可用。新批次对已有文章的 `REUSED_COMPLETE` 处理继续保留原归属，链接最终成果，不复制为新待编辑稿件。

## 执行顺序与失败恢复

1. 在操作 05 的现有人工确认后，验证全部闸门和素材、生成交付目录。使用现有暂存、文件哈希和原子替换机制；人工改动或额外文件不能被静默覆盖。
2. 清理前验证最终正文、有图文章原图和授权文件与发布材料一致；确认没有待处理请求、外部文件引用或不安全路径。收集程序管理的待删路径。
3. 在互斥的工作区操作窗口内，事务写入清理状态和清单、切换文件引用并记录审计；工作区验证同步支持此状态。不得在仍有并发写入时遍历删除。
4. 删除清单中的过程文件和批次目录。清理不跟随符号链接；拒绝不安全目录、仓库之外的路径和意外类型。删除前核对清单，不删除清理开始后出现的未知文件。
5. 全部清理成功后记录 `FINAL_ONLY`，更新首页并打开交付目录。交付保留且删除过程失败时，显示“已导出，清理未完成”，不能宣称全部完成。

在第 3 步之前失败保留过程材料。第 3 步之后中断，SQLite 的新路径仍指向已验证的最终成果，清理记录支持再次执行操作 05 继续删除；已删除对象可跳过，不重复审批。最终成果缺失、被改变或清理清单不符时暂停清理并提供诊断，不能删除剩余恢复素材。清理故障不恢复已删除的过程文件，界面必须明确这一点。

现有历史批次只有显式执行操作 05 才应用新策略，包括本次测试批次；完成实现及验证后再对该批次执行。仅运行 status、refresh 或 init 不触发删除。

## 工作区迁移与验证

迁移准入、预检、复制验证和终态验证需要识别清理状态：最终文章和图片允许位于 `workspace/completed/`；已解除引用的过程文件不再要求存在；已清理批次不要求原 CSV、批次启动器、请求、历史核验和完整发布包。仍验证批次归属、有效成员、最终文件范围与交付完整性，不能通过状态标记跳过全部检查。

`CLEANING` 状态允许清单中的过程文件部分存在，且只能用于继续清理，不能恢复旧工作流。旧迁移备份与恢复树保持原验证和保护机制，不由清理程序删除或篡改。

## 验证要求

先写失败测试，覆盖有图、无图、历史已打包批次和跨批次引用。清理前后比较数据库去重字段、实际 duplicate-check 结果、相同 CSV 重入和新 CSV 对同事件的去重结果。

验证过程目录确实消失，最终字节及授权保留，未完成批次和外部原文件不变；状态、刷新、复用、可选 URL 登记及迁移检查正常且不重建过程文件。注入导出、事务、删除和中断故障，证明未验证交付不清理，部分清理可恢复，已有人工修改不覆盖，不跟随符号链接、不删跨批次文件。

完成后运行完整 pytest、隔离 demo 和 diff 检查；更新 WORKFLOW、ROADMAP、DATA_MODEL、中文操作文档及相关示例。真实测试批次执行前后核对最终文章数、数据库记录及去重结果，报告实际保留目录和清理结果。
